================================================================================
  SFMShop — руководство по HTTP-методам и статусам ответов
================================================================================

Базовый URL API (пример): http://localhost:8000

Общие правила:
  - GET    — чтение данных (без изменения ресурса)
  - POST   — создание нового ресурса
  - PUT    — полное обновление существующего ресурса
  - DELETE — удаление ресурса

  - 200 OK           — успешное чтение или обновление
  - 201 Created      — ресурс успешно создан
  - 400 Bad Request  — неверные данные в запросе (валидация)
  - 404 Not Found    — ресурс не найден
  - 500 Internal Server Error — ошибка на сервере (БД, код)

Формат данных: JSON (Content-Type: application/json)


--------------------------------------------------------------------------------
1. Получение списка товаров
--------------------------------------------------------------------------------

HTTP метод : GET
Путь       : /products
Успех      : 200 OK
Ошибки     : 500 — сбой при обращении к БД

Описание:
  Возвращает все товары из таблицы products (id, name, price, quantity).
  Соответствует функции get_all_products() в src/database/connection.py.

Пример запроса:
  GET /products HTTP/1.1
  Host: localhost:8000
  Accept: application/json

Пример успешного ответа (200):
  HTTP/1.1 200 OK
  Content-Type: application/json

  [
    {"id": 1, "name": "Ноутбук", "price": 50000.00, "quantity": 10},
    {"id": 2, "name": "Мышь", "price": 1500.00, "quantity": 20},
    {"id": 3, "name": "Клавиатура", "price": 3000.00, "quantity": 15}
  ]

Пример ошибки сервера (500):
  HTTP/1.1 500 Internal Server Error
  Content-Type: application/json

  {"error": "Не удалось получить список товаров"}


--------------------------------------------------------------------------------
2. Получение товара по ID
--------------------------------------------------------------------------------

HTTP метод : GET
Путь       : /products/{id}
             Пример: /products/1
Успех      : 200 OK
Ошибки     : 404 — товар с таким id не существует
             500 — ошибка сервера

Описание:
  Возвращает один товар по первичному ключу id.

Пример запроса:
  GET /products/1 HTTP/1.1
  Host: localhost:8000
  Accept: application/json

Пример успешного ответа (200):
  HTTP/1.1 200 OK
  Content-Type: application/json

  {"id": 1, "name": "Ноутбук", "price": 50000.00, "quantity": 10}

Пример ответа «не найден» (404):
  HTTP/1.1 404 Not Found
  Content-Type: application/json

  {"error": "Товар с id=99 не найден"}


--------------------------------------------------------------------------------
3. Создание нового заказа
--------------------------------------------------------------------------------

HTTP метод : POST
Путь       : /orders
Успех      : 201 Created
Ошибки     : 400 — неверное тело запроса (нет user_id, пустой список товаров,
             отрицательная сумма)
             404 — пользователь не найден
             500 — ошибка при записи в БД

Описание:
  Создаёт заказ в таблице orders и позиции в order_items.
  Соответствует create_order() и логике модели Order в src/models/order.py.

Тело запроса (JSON):
  {
    "user_id": 1,
    "items": [
      {"product_id": 1, "quantity": 1},
      {"product_id": 2, "quantity": 2}
    ]
  }

Пример запроса:
  POST /orders HTTP/1.1
  Host: localhost:8000
  Content-Type: application/json

  {"user_id": 1, "items": [{"product_id": 1, "quantity": 1}]}

Пример успешного ответа (201):
  HTTP/1.1 201 Created
  Content-Type: application/json
  Location: /orders/3

  {
    "id": 3,
    "user_id": 1,
    "total": 50000.00,
    "created_at": "2024-01-15T10:00:00",
    "items": [
      {"product_id": 1, "product_name": "Ноутбук", "quantity": 1, "price": 50000.00}
    ]
  }

Пример ошибки валидации (400):
  HTTP/1.1 400 Bad Request
  Content-Type: application/json

  {"error": "Поле user_id обязательно"}


--------------------------------------------------------------------------------
4. Обновление данных товара
--------------------------------------------------------------------------------

HTTP метод : PUT
Путь       : /products/{id}
             Пример: /products/2
Успех      : 200 OK
Ошибки     : 400 — невалидные данные (например, отрицательная цена;
             см. ValidationError в src/models/product.py)
             404 — товар не найден
             500 — ошибка сервера

Описание:
  Полностью обновляет поля товара (name, price, quantity).
  Частичное обновление только цены в БД: update_product_price() —
  на уровне API всё равно используется PUT с полным телом.

Тело запроса (JSON):
  {
    "name": "Мышь беспроводная",
    "price": 1800.00,
    "quantity": 25
  }

Пример запроса:
  PUT /products/2 HTTP/1.1
  Host: localhost:8000
  Content-Type: application/json

  {"name": "Мышь", "price": 1800.00, "quantity": 25}

Пример успешного ответа (200):
  HTTP/1.1 200 OK
  Content-Type: application/json

  {"id": 2, "name": "Мышь", "price": 1800.00, "quantity": 25}

Пример ошибки валидации (400):
  HTTP/1.1 400 Bad Request
  Content-Type: application/json

  {"error": "Цена не может быть отрицательной"}


--------------------------------------------------------------------------------
5. Удаление товара
--------------------------------------------------------------------------------

HTTP метод : DELETE
Путь       : /products/{id}
             Пример: /products/5
Успех      : 200 OK (с телом подтверждения) или 204 No Content (без тела)
Ошибки     : 404 — товар не найден
             409 — товар нельзя удалить (есть в активных заказах)
             500 — ошибка сервера

Описание:
  Удаляет запись из таблицы products по id.
  Аналог операции удаления в REST; в проекте для заказов есть delete_order().

Пример запроса:
  DELETE /products/5 HTTP/1.1
  Host: localhost:8000

Пример успешного ответа (200):
  HTTP/1.1 200 OK
  Content-Type: application/json

  {"message": "Товар с id=5 удалён"}

Пример ответа «не найден» (404):
  HTTP/1.1 404 Not Found
  Content-Type: application/json

  {"error": "Товар с id=5 не найден"}


--------------------------------------------------------------------------------
6. Получение заказов пользователя
--------------------------------------------------------------------------------

HTTP метод : GET
Путь       : /users/{user_id}/orders
             Альтернатива: GET /orders?user_id=1
Успех      : 200 OK
Ошибки     : 404 — пользователь не найден
             500 — ошибка сервера

Описание:
  Возвращает заказы пользователя, при необходимости с деталями товаров.
  Соответствует get_user_orders() и get_user_order_history() в
  src/database/connection.py и src/database/queries.py.

Пример запроса:
  GET /users/1/orders HTTP/1.1
  Host: localhost:8000
  Accept: application/json

Пример успешного ответа (200):
  HTTP/1.1 200 OK
  Content-Type: application/json

  {
    "user_id": 1,
    "orders": [
      {
        "id": 1,
        "total": 50000.00,
        "created_at": "2024-01-15T10:00:00",
        "items": [
          {"product_name": "Ноутбук", "quantity": 1, "price": 50000.00}
        ]
      }
    ]
  }

Пример пустого списка (200 — заказов нет, но пользователь есть):
  HTTP/1.1 200 OK
  Content-Type: application/json

  {"user_id": 3, "orders": []}

Пример ответа «пользователь не найден» (404):
  HTTP/1.1 404 Not Found
  Content-Type: application/json

  {"error": "Пользователь с id=99 не найден"}
