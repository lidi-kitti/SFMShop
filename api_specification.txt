================================================================================
1. ОБЩИЕ СВЕДЕНИЯ
================================================================================

HTTP-методы:
  GET    — получение данных
  POST   — создание ресурса
  PUT    — полное обновление ресурса
  DELETE — удаление ресурса

Коды статусов:
  200 OK                    — успешное чтение, обновление или удаление
  201 Created               — ресурс успешно создан
  400 Bad Request           — неверные или неполные данные в запросе
  404 Not Found             — ресурс не найден
  500 Internal Server Error — внутренняя ошибка сервера (БД, код)

Связь с БД проекта:
  products   — таблица товаров
  orders     — таблица заказов
  order_items — позиции заказа
  users      — таблица пользователей


================================================================================
2. МОДЕЛИ ДАННЫХ
================================================================================

Product (товар):
  {
    "id": integer,          — только в ответах (автоинкремент)
    "name": string,         — обязательно, до 200 символов
    "price": number,        — обязательно, >= 0, до 2 знаков после запятой
    "quantity": integer     — обязательно, >= 0, остаток на складе
  }

Order (заказ):
  {
    "id": integer,
    "user_id": integer,
    "total": number,
    "created_at": string,   — ISO 8601, например "2024-01-15T10:00:00"
    "items": [OrderItem]    — опционально, в детальных ответах
  }

OrderItem (позиция заказа):
  {
    "product_id": integer,
    "product_name": string, — только в ответах
    "quantity": integer,
    "price": number         — цена на момент заказа
  }

User (пользователь, справочно):
  {
    "id": integer,
    "name": string,
    "email": string
  }

Error (тело ошибки):
  {
    "error": string,          — краткое описание
    "details": object       — опционально, поля с ошибками валидации
  }


================================================================================
3. ОБРАБОТКА ОШИБОК
================================================================================

Все ошибки возвращаются в формате JSON с полем "error".

400 Bad Request — неправильные данные
  Когда:
    - отсутствуют обязательные поля в теле запроса
    - неверный тип данных (строка вместо числа)
    - отрицательная цена или quantity
    - пустой список items при создании заказа
    - невалидный email (если применимо)
  Пример:
    HTTP/1.1 400 Bad Request
    Content-Type: application/json

    {
      "error": "Неверные данные запроса",
      "details": {
        "price": "Цена не может быть отрицательной",
        "name": "Поле name обязательно"
      }
    }

404 Not Found — ресурс не найден
  Когда:
    - товар, заказ или пользователь с указанным id не существует
  Пример:
    HTTP/1.1 404 Not Found
    Content-Type: application/json

    {"error": "Товар с id=99 не найден"}

500 Internal Server Error — ошибка сервера
  Когда:
    - сбой подключения к PostgreSQL
    - необработанное исключение в коде
  Пример:
    HTTP/1.1 500 Internal Server Error
    Content-Type: application/json

    {"error": "Внутренняя ошибка сервера"}

4. ENDPOINTS: ТОВАРЫ (PRODUCTS)
================================================================================

--------------------------------------------------------------------------------
4.1. GET /products — список товаров
--------------------------------------------------------------------------------

Описание:
  Возвращает все товары из каталога.
  Аналог: get_all_products() в src/database/connection.py.

HTTP метод     : GET
Путь           : /products

Path parameters: нет

Query parameters (опционально):
  limit  (integer) — максимум записей в ответе, по умолчанию без ограничения
  offset (integer) — смещение для пагинации, по умолчанию 0
  min_price (number) — фильтр: цена >= min_price
  max_price (number) — фильтр: цена <= max_price

Тело запроса   : нет

Статусы ответов:
  200 OK  — список получен (может быть пустым массивом [])
  500     — ошибка при чтении из БД

Пример запроса:
  GET /api/v1/products HTTP/1.1
  Host: localhost:8000
  Accept: application/json

Пример запроса с параметрами:
  GET /api/v1/products?limit=10&offset=0&min_price=1000 HTTP/1.1
  Host: localhost:8000
  Accept: application/json

Пример успешного ответа (200):
  HTTP/1.1 200 OK
  Content-Type: application/json

  [
    {"id": 1, "name": "Ноутбук", "price": 50000.00, "quantity": 10},
    {"id": 2, "name": "Мышь", "price": 1500.00, "quantity": 20},
    {"id": 3, "name": "Клавиатура", "price": 3000.00, "quantity": 15}
  ]

Пример ошибки (500):
  HTTP/1.1 500 Internal Server Error
  Content-Type: application/json

  {"error": "Не удалось получить список товаров"}


--------------------------------------------------------------------------------
4.2. GET /products/{id} — товар по ID
--------------------------------------------------------------------------------

Описание:
  Возвращает один товар по первичному ключу.

HTTP метод     : GET
Путь           : /products/{id}

Path parameters:
  id (integer, обязательный) — идентификатор товара

Query parameters: нет

Тело запроса   : нет

Статусы ответов:
  200 OK  — товар найден
  404     — товар с таким id не существует
  400     — id не является числом
  500     — ошибка сервера

Пример запроса:
  GET /api/v1/products/1 HTTP/1.1
  Host: localhost:8000
  Accept: application/json

Пример успешного ответа (200):
  HTTP/1.1 200 OK
  Content-Type: application/json

  {"id": 1, "name": "Ноутбук", "price": 50000.00, "quantity": 10}

Пример ошибки (404):
  HTTP/1.1 404 Not Found
  Content-Type: application/json

  {"error": "Товар с id=99 не найден"}


--------------------------------------------------------------------------------
4.3. POST /products — создание товара
--------------------------------------------------------------------------------

Описание:
  Добавляет новый товар в каталог.
  Аналог: add_product() в src/database/connection.py.

HTTP метод     : POST
Путь           : /products

Path parameters: нет
Query parameters: нет

Тело запроса (JSON, обязательно):
  {
    "name": string,      — обязательно
    "price": number,     — обязательно, >= 0
    "quantity": integer  — обязательно, >= 0; по умолчанию 5 в БД
  }

Статусы ответов:
  201 Created — товар создан
  400         — невалидные данные
  500         — ошибка при записи в БД

Пример запроса:
  POST /api/v1/products HTTP/1.1
  Host: localhost:8000
  Content-Type: application/json

  {
    "name": "Монитор",
    "price": 20000.00,
    "quantity": 5
  }

Пример успешного ответа (201):
  HTTP/1.1 201 Created
  Content-Type: application/json
  Location: /api/v1/products/6

  {
    "id": 6,
    "name": "Монитор",
    "price": 20000.00,
    "quantity": 5
  }

Пример ошибки валидации (400):
  HTTP/1.1 400 Bad Request
  Content-Type: application/json

  {
    "error": "Неверные данные запроса",
    "details": {
      "price": "Цена не может быть отрицательной"
    }
  }


--------------------------------------------------------------------------------
4.4. PUT /products/{id} — обновление товара
--------------------------------------------------------------------------------

Описание:
  Полностью заменяет данные товара (name, price, quantity).
  Аналог: update_product_price() и set_price() в модели Product.

HTTP метод     : PUT
Путь           : /products/{id}

Path parameters:
  id (integer, обязательный) — идентификатор товара

Query parameters: нет

Тело запроса (JSON, обязательно — все поля):
  {
    "name": string,
    "price": number,
    "quantity": integer
  }

Статусы ответов:
  200 OK  — товар обновлён
  400     — невалидные данные (отрицательная цена и т.д.)
  404     — товар не найден
  500     — ошибка сервера

Пример запроса:
  PUT /api/v1/products/2 HTTP/1.1
  Host: localhost:8000
  Content-Type: application/json

  {
    "name": "Мышь беспроводная",
    "price": 1800.00,
    "quantity": 25
  }

Пример успешного ответа (200):
  HTTP/1.1 200 OK
  Content-Type: application/json

  {
    "id": 2,
    "name": "Мышь беспроводная",
    "price": 1800.00,
    "quantity": 25
  }

Пример ошибки (404):
  HTTP/1.1 404 Not Found
  Content-Type: application/json

  {"error": "Товар с id=2 не найден"}


--------------------------------------------------------------------------------
4.5. DELETE /products/{id} — удаление товара
--------------------------------------------------------------------------------

Описание:
  Удаляет товар из каталога по id.

HTTP метод     : DELETE
Путь           : /products/{id}

Path parameters:
  id (integer, обязательный) — идентификатор товара

Query parameters: нет
Тело запроса   : нет

Статусы ответов:
  200 OK  — товар удалён (с телом подтверждения)
  404     — товар не найден
  500     — ошибка сервера

Пример запроса:
  DELETE /api/v1/products/5 HTTP/1.1
  Host: localhost:8000

Пример успешного ответа (200):
  HTTP/1.1 200 OK
  Content-Type: application/json

  {"message": "Товар с id=5 удалён"}

Пример ошибки (404):
  HTTP/1.1 404 Not Found
  Content-Type: application/json

  {"error": "Товар с id=5 не найден"}

5. ENDPOINTS: ЗАКАЗЫ (ORDERS)
================================================================================

--------------------------------------------------------------------------------
5.1. GET /orders — список заказов
--------------------------------------------------------------------------------

Описание:
  Возвращает все заказы или отфильтрованный список.
  Данные из таблицы orders (+ опционально order_items).

HTTP метод     : GET
Путь           : /orders

Path parameters: нет

Query parameters (опционально):
  user_id (integer) — фильтр заказов по пользователю
  limit   (integer) — лимит записей
  offset  (integer) — смещение для пагинации
  sort    (string)  — сортировка: "created_at_desc" (по умолчанию), "total_asc"

Тело запроса   : нет

Статусы ответов:
  200 OK  — список получен
  400     — невалидный user_id в query
  500     — ошибка сервера

Пример запроса:
  GET /api/v1/orders HTTP/1.1
  Host: localhost:8000
  Accept: application/json

Пример запроса с фильтром:
  GET /api/v1/orders?user_id=1&limit=20 HTTP/1.1
  Host: localhost:8000
  Accept: application/json

Пример успешного ответа (200):
  HTTP/1.1 200 OK
  Content-Type: application/json

  [
    {
      "id": 1,
      "user_id": 1,
      "total": 50000.00,
      "created_at": "2024-01-15T10:00:00"
    },
    {
      "id": 2,
      "user_id": 2,
      "total": 3500.00,
      "created_at": "2024-01-16T14:30:00"
    }
  ]

Пример пустого списка (200):
  HTTP/1.1 200 OK
  Content-Type: application/json

  []


--------------------------------------------------------------------------------
5.2. POST /orders — создание заказа
--------------------------------------------------------------------------------

Описание:
  Создаёт новый заказ: запись в orders и позиции в order_items.
  Пересчитывает total по ценам товаров и количеству.
  Аналог: create_order() и модель Order в src/models/order.py.

HTTP метод     : POST
Путь           : /orders

Path parameters: нет
Query parameters: нет

Тело запроса (JSON, обязательно):
  {
    "user_id": integer,           — обязательно, должен существовать в users
    "items": [                    — обязательно, минимум 1 элемент
      {
        "product_id": integer,    — обязательно
        "quantity": integer       — обязательно, > 0
      }
    ]
  }

Статусы ответов:
  201 Created — заказ создан
  400         — невалидные данные, пустой items, quantity <= 0
  404         — user_id или product_id не найден
  500         — ошибка при записи в БД

Пример запроса:
  POST /api/v1/orders HTTP/1.1
  Host: localhost:8000
  Content-Type: application/json

  {
    "user_id": 1,
    "items": [
      {"product_id": 1, "quantity": 1},
      {"product_id": 2, "quantity": 2}
    ]
  }

Пример успешного ответа (201):
  HTTP/1.1 201 Created
  Content-Type: application/json
  Location: /api/v1/orders/3

  {
    "id": 3,
    "user_id": 1,
    "total": 53000.00,
    "created_at": "2024-01-20T12:00:00",
    "items": [
      {
        "product_id": 1,
        "product_name": "Ноутбук",
        "quantity": 1,
        "price": 50000.00
      },
      {
        "product_id": 2,
        "product_name": "Мышь",
        "quantity": 2,
        "price": 1500.00
      }
    ]
  }

Пример ошибки — пользователь не найден (404):
  HTTP/1.1 404 Not Found
  Content-Type: application/json

  {"error": "Пользователь с id=99 не найден"}

Пример ошибки валидации (400):
  HTTP/1.1 400 Bad Request
  Content-Type: application/json

  {
    "error": "Неверные данные запроса",
    "details": {
      "items": "Список товаров не может быть пустым"
    }
  }

6. ENDPOINTS: ЗАКАЗЫ ПОЛЬЗОВАТЕЛЯ (USERS)
================================================================================

--------------------------------------------------------------------------------
6.1. GET /users/{id}/orders — заказы пользователя
--------------------------------------------------------------------------------

Описание:
  Возвращает все заказы указанного пользователя с деталями позиций.
  Аналог: get_user_orders(), get_user_order_history() в src/database/.

HTTP метод     : GET
Путь           : /users/{id}/orders

Path parameters:
  id (integer, обязательный) — идентификатор пользователя (user_id)

Query parameters (опционально):
  include_items (boolean) — true: с позициями товаров (по умолчанию true)
  limit  (integer) — лимит заказов
  offset (integer) — смещение

Тело запроса   : нет

Статусы ответов:
  200 OK  — заказы получены (массив может быть пустым)
  404     — пользователь не найден
  400     — id не является числом
  500     — ошибка сервера

Пример запроса:
  GET /api/v1/users/1/orders HTTP/1.1
  Host: localhost:8000
  Accept: application/json

Пример успешного ответа (200):
  HTTP/1.1 200 OK
  Content-Type: application/json

  {
    "user_id": 1,
    "user_name": "Иван",
    "orders": [
      {
        "id": 1,
        "total": 50000.00,
        "created_at": "2024-01-15T10:00:00",
        "items": [
          {
            "product_id": 1,
            "product_name": "Ноутбук",
            "quantity": 1,
            "price": 50000.00
          }
        ]
      }
    ]
  }

Пример пустого списка заказов (200):
  HTTP/1.1 200 OK
  Content-Type: application/json

  {
    "user_id": 3,
    "user_name": "Петр",
    "orders": []
  }

Пример ошибки (404):
  HTTP/1.1 404 Not Found
  Content-Type: application/json

  {"error": "Пользователь с id=99 не найден"}

ПРИМЕРЫ cURL (для тестирования)
================================================================================

# Список товаров

# Товар по ID
curl -X GET "http://localhost:8000/api/v1/products/1"

# Создание товара
curl -X POST "http://localhost:8000/api/v1/products" \
  -H "Content-Type: application/json" \
  -d "{\"name\":\"Наушники\",\"price\":5000,\"quantity\":12}"

# Обновление товара
curl -X PUT "http://localhost:8000/api/v1/products/2" \
  -H "Content-Type: application/json" \
  -d "{\"name\":\"Мышь\",\"price\":1800,\"quantity\":25}"

curl -X DELETE "http://localhost:8000/api/v1/products/5"

# Создание заказа
curl -X POST "http://localhost:8000/api/v1/orders" \
  -H "Content-Type: application/json" \
  -d "{\"user_id\":1,\"items\":[{\"product_id\":1,\"quantity\":1}]}"

# Заказы пользователя
